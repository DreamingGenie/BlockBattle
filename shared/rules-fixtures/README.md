# 공용 게임 규칙 시험 데이터

FE 엔진(`frontend/src/engine`), 친구 대전 서버 재계산(BE, T-12), AI 서버(T-7)가 **같은 JSON을 그대로 읽어** 같은 결과를 내는지 확인한다(CON-002). 규칙 원본은 요구사항 GR-01~GR-08이다.

| 파일 | 내용 | 엔진이 맞춰야 할 것 |
| --- | --- | --- |
| `bag.json` | 시드별 처음 21개 블록 | mulberry32(시드 하위 32비트) + Fisher-Yates 7-bag |
| `srs.json` | 모양·SRS 킥 표·회전 사례 | 회전 결과 위치(또는 실패 = null) |
| `lock-cases.json` | lock 한 번의 입력과 결과 | 보드·줄 수·T-스핀·퍼펙트·B2B·점수·공격·상쇄·방해 줄·다음 상태 |
| `timing.json` | 상수 | 낙하 간격·고정 지연·자동 반복·미리 보기 수 |

- 좌표: 행 0이 맨 위(숨김 2행 포함 22행), 열 0이 왼쪽이다. 블록 위치 x·y는 회전 상자(I·O 4x4, 나머지 3x3)의 왼쪽 위 칸이다.
- 보드는 `bottomRows`(아래쪽 행만 위→아래 순서)로 적고, 나머지 위 행은 빈칸이다. 220자 board 문자열과 같은 문자(0·IOTSZJL·G)를 쓴다.
- `bag.json`의 기대값은 TS 구현과 별개인 Python 참조 구현 `gen_bag.py`로 만들었다. 다시 만들려면 `python shared/rules-fixtures/gen_bag.py`를 실행한다.
- `lock-cases.json`의 기대값은 요구사항 예시(3레벨 B2B 테트리스 콤보 2 = 3,900, 대기 3줄 + 5줄 공격 → 2줄 전송)와 규칙 표로 손계산한 값이다.

## 설계에 값이 없어 정한 것 (BEEZ 작업 T-2 계획 unlinked)

- SRS 킥 표는 표준 SRS 값을 쓴다.
- 생성 위치는 상자 왼쪽 열 3·맨 위 행 0이다. I는 행 1의 열 3~6에 놓이고, 나머지는 열 3~5(O는 4~5)에 놓인다.
- 방해 줄의 구멍 열은 엔진 입력(`holeColumn`)으로 받는다. 난수원은 서버·vs AI가 정한다.
- 묶음 여러 개가 함께 올라오면 받은 순서대로 아래에서 밀어 올린다. 그래서 먼저 받은 묶음이 위에 놓인다.
- T-스핀의 "마지막 성공 동작": 회전 뒤 한 칸이라도 이동(좌우·중력·소프트·거리 1 이상의 하드 드롭)하면 회전이 아니다.
