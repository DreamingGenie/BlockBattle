# 테트리스 대전 게임 — 기획서

개정 2판 · 2026-11-12 · 작성 오션(팀장)

브라우저에서 바로 하는 블록 퍼즐 대전 게임이다. 설치·회원가입 없이 닉네임만 넣고 들어와 혼자 점수를 겨루거나, AI와 붙거나, 게임 코드 하나로 친구와 1:1 대전을 한다.

이 문서는 왜 만들고 무엇을 어디까지 만드는지를 정한다. 게임 규칙·정책의 정확한 값은 요구사항 명세서(GR·BR 번호)가, 저장 구조는 ERD 명세서가, 요청·응답 형식은 API 명세서가 원본이다. 이 문서는 그 값을 다시 적지 않고 번호로 가리킨다.

## 1. 배경과 문제

- 기존 웹 블록 퍼즐은 혼자 하는 것이 대부분이고, 친구와 붙으려면 앱 설치·계정 생성·친구 추가를 거쳐야 한다.
- 점심시간 10분처럼 짧은 틈에 "링크 하나 보내고 바로 한 판"을 하고 싶은 수요가 있다.
- 실력 차이가 큰 친구끼리는 재미가 금방 떨어진다. 혼자 연습할 상대(AI)가 있으면 다시 찾아올 이유가 생긴다.

## 2. 목표와 측정

| 구분 | 목표 | 측정 방법 |
| --- | --- | --- |
| 진입 | 첫 접속부터 첫 게임 시작까지 30초 이내 | 사용자별 users.created_at에서 그 사용자의 첫 matches.started_at까지 걸린 시간의 중앙값 |
| 대전 | 초대 링크로 들어온 사람의 70% 이상이 실제로 한 판을 끝냄 | 방 입장(join) 성공 수 대비, 그 방에서 그 사용자가 참가한 FINISHED 경기가 1개 이상인 수 |
| 재방문 | 첫 게임을 끝낸 사용자의 25%가 7일 안에 다시 와서 1판 이상 끝냄 | 첫 FINISHED 경기의 종료일로 주간 코호트를 묶고, 다음 날부터 7일 안에 FINISHED 경기가 1개 이상 있는 사용자 수(users.id 중복 제거) ÷ 코호트 사용자 수 |
| 공정성 | 같은 시드면 두 사람이 같은 블록 순서를 받음 | 친구 대전 경기마다 서버가 시드로 다시 만든 블록 순서와 두 클라이언트 순서가 같은지 로그로 확인 |

matches 행은 게임이 시작될 때 만들어지므로(BR-02) started_at이 곧 게임 시작 시각이다.

## 3. 대상 사용자

- **직장인·학생 친구 무리**: 메신저로 링크를 돌려 짧게 한 판 붙는다.
- **혼자 연습하는 사람**: 랭킹 점수를 올리거나 AI 난이도를 올려 가며 실력을 키운다.

## 4. 게임 모드

### 4.1 싱글 (SOLO)

- 표준 보드와 조작, 7-bag, 홀드 1칸, 다음 블록 5개 미리 보기(GR-01~GR-04).
- 레벨은 지운 줄 10줄마다 1씩 오르고, 낙하 속도가 빨라진다(GR-03).
- 끝나면 점수를 저장하고 싱글 랭킹(최고 점수 TOP 10 + 내 순위)을 보여 준다. 클라이언트가 판정한 점수는 서버가 상한 검사로 걸러 랭킹을 지킨다(BR-07).

### 4.2 vs AI (AI)

- 화면을 반으로 나눠 왼쪽은 나, 오른쪽은 AI 보드. 두 보드 모두 FE의 같은 게임 엔진이 돌리고, 같은 시드를 쓴다.
- 난이도 EASY·NORMAL·HARD. AI 서버의 탐색 깊이와 FE의 입력 재생 속도로 조절한다.
- AI 서버가 150ms 안에 답하지 않거나 오류를 내면 FE 규칙 AI가 그 수를 대신 둔다. 게임은 멈추지 않는다(FR-AI-02).
- 공격·방해 줄 규칙은 친구 대전과 같다(GR-08). 경기 판정은 클라이언트가 하고 결과만 서버에 저장한다.

### 4.3 친구 대전 (FRIEND)

- 방장이 방을 만들면 6자리 게임 코드와 초대 URL이 나온다. 정원은 2명.
- 둘 다 "준비"를 누르면 3초 카운트다운 뒤 같은 시드로 동시에 시작한다.
- 블록을 고정할 때마다 서버에 알리고, 서버가 줄 삭제·점수·공격량을 다시 계산해 상대에게 보드와 방해 줄을 보낸다(FR-BAT-01, BR-05, GR-08).
- 먼저 천장에 닿는 사람이 진다. 연결이 끊기면 10초 동안 재접속을 기다리고, 그 안에 복귀하면 상태를 복원해 이어서 한다. 두 사람이 모두 끊긴 채 10초가 지나면 경기는 ABORTED, 한 사람만 끊겼으면 끊긴 사람의 패배로 처리한다(BR-06).
- 기본은 1판이다. 3판 2선승과 재대결은 Should 범위다.

## 5. 범위

| 우선순위 | 기능 |
| --- | --- |
| Must | 게스트 로그인·토큰 재발급·로그아웃, 내 정보·전적, 싱글 플레이·결과 저장·랭킹, vs AI 3단계와 폴백, 친구 대전(방 생성·조회·입장·퇴장·준비·대전·결과·끊김 처리), 최근 경기 목록·상세 |
| Should | 재대결, 3판 2선승, 카카오 계정 연결과 카카오 로그인으로 게스트 계정 이어 받기 |
| Won't (이번 범위 밖) | 공개 매칭(랜덤 상대), 3인 이상 대전, 관전, 채팅, 모바일 앱·터치 조작, 결제 |

## 6. 기술 구성

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| FE | React 19 + TypeScript + Canvas | 60fps 보드 렌더링, 게임 루프는 FE가 소유 |
| BE | Spring Boot 3 (Java 21), STOMP over WebSocket | 방·대전 중계, 서버 재계산 |
| AI | Python FastAPI | 수 탐색(빔 서치 + 휴리스틱 평가) |
| 저장 | MySQL 8(회원·방 이력·경기 기록·전적), Redis 7(진행 중 방·경기 상태, 랭킹 캐시, Refresh 토큰) | 진행 중 상태는 휘발성, 기록은 영속 |
| 배포 | Docker Compose, Nginx(WebSocket 프록시), 단일 EC2 | 4주 프로젝트 규모 |

## 7. 팀과 역할 (4인)

| 이름 | 역할 | 담당 |
| --- | --- | --- |
| 오션 | 팀장·BE | 인증, 방·대전 중계, 결과 저장 |
| 민수 | FE | 게임 엔진(SRS 회전, 7-bag, 점수·공격 계산), 게임 화면 |
| 지아 | FE | 로비·방·결과·랭킹 화면, STOMP 클라이언트 |
| 태오 | AI·인프라 | AI 서버, 배포, 부하 시험 |

게임 엔진 규칙(GR)은 FE와 BE가 같은 결과를 내야 한다. 친구 대전 서버 재계산이 FE 엔진과 같은 규칙을 쓰도록, 규칙별 입력·기대 출력 예시를 공용 시험 데이터로 둔다.

## 8. 일정 (4주)

| 주차 | 목표 |
| --- | --- |
| 1주 | 기획·설계 확정, 게임 엔진 싱글 플레이 동작, 게스트 로그인 |
| 2주 | 싱글 결과 저장·랭킹, 내 정보·기록, AI 서버 EASY 동작 |
| 3주 | 친구 대전(방·준비·lock 중계·공격·게임오버), AI 3단계 |
| 4주 | 끊김 처리, Should 범위, 부하 확인(동시 100방), 버그 수정, 발표 |

## 9. 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 클라이언트 조작(점수·공격량 위조) | 친구 대전은 서버가 lock마다 다시 계산하고 맞지 않으면 INVALID_LOCK(BR-05). 싱글·AI는 점수 상한 검사로 랭킹에서 뺀다(BR-07) |
| 네트워크 지연으로 공격이 늦게 도착 | 방해 줄은 줄을 지우지 못한 다음 고정 때 올라온다(GR-08). 서버 메시지의 sentAt으로 지연을 잰다 |
| AI 서버 응답 지연·장애 | 150ms 또는 오류 시 FE 규칙 AI로 대체(FR-AI-02) |
| FE·BE 게임 규칙 불일치 | 공용 시험 데이터로 두 엔진을 같은 입력에 돌려 비교 |
| "Tetris" 상표 | 공개 배포 시 서비스 이름을 바꾼다(가칭 "블록 배틀") |
