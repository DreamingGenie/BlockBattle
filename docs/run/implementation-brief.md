## 작업 하나를 처리하는 순서

시작할 때 MCP 도구 목록을 한 번 보고 실제 도구 이름을 쓴다. BEEZ 연결 매뉴얼은 `C:\git\BEEZ\docs\guides\agent-connection.md`이다.

1. 작업과 설계 맥락을 받는다. `get_task`로 작업을 보고 `get_development_context`로 컨텍스트 패킷을 받는다.
2. 구현 계획을 올리고 검증한다. `upsert_task_plan`에 범위·설계 참조(IMPLEMENTS/CHANGES)·패킷을 넣고, 검증이 PASS일 때만 시작한다.
3. 구현하고 시험한다. 시험은 각 규칙·계약에서 온 것만 쓴다.
4. 커밋한다. `main`에 작업 하나당 커밋 하나 이상, 메시지는 `feat: 설명 (T-n)`이다. 원격이 없으니 push는 하지 않는다.
5. 판단 기록(`write_context`)을 남기고 완료를 보고한다.
6. `docs/run/run-log.md`에 한 줄을 더한다. 시작·끝 시각, 검증 결과·걸린 시간, 커밋, 막힌 곳을 적는다.

- 순서는 의존을 따른다. 먼저 T-1(MySQL·Redis 저장 구조)과 T-2(결정론적 게임 엔진·공용 규칙 시험)를 하고, 그다음 인증, 싱글, AI, 방, 대전 순으로 간다.
- 기술 구성은 기획서 6장을 따른다.
  - `frontend/`: React 19 + TS + Vite + Canvas
  - `backend/`: Spring Boot 3, Java 21
  - `ai/`: FastAPI
  - `infra/`: docker compose로 MySQL 8과 Redis 7
- Docker Desktop이 꺼져 있으면 전진님께 켜 달라고 한다.
