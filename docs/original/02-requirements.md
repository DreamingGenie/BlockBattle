# 테트리스 대전 게임 — 요구사항 명세서

Nov 10, 2026 · @ocean

기획서의 Must · Should 범위를 기능 요구사항(FR)과 비기능 요구사항(NFR)으로 나눈다. ID는 API 명세서의 "요구사항" 칸과 맞춘다.

## 1. 기능 요구사항

### 1.1 회원 (USR)

| ID | 요구사항 | 우선순위 | 수용 기준 |
| --- | --- | --- | --- |
| FR-USR-01 | 닉네임만으로 게스트 로그인한다 | Must | 2\~10자 한글 · 영문 · 숫자, 같은 닉네임은 4자리 태그로 구분, Access(1시간) · Refresh(7일) 토큰 발급 |
| FR-USR-02 | 게스트 계정을 카카오 계정으로 이어 받는다 | Should | 연결 후에도 같은 userId · 전적 유지, 이미 연결된 카카오 계정이면 거부 |
| FR-USR-03 | 내 정보와 전적 요약을 본다 | Must | 닉네임#태그, 싱글 최고 점수 · 판 수, vs AI 승패, 친구 대전 승패 |
| FR-USR-04 | 토큰 재발급과 로그아웃 | Must | Refresh 토큰으로 재발급, 로그아웃 시 Redis의 Refresh 삭제 |

### 1.2 싱글 (SOL)

| ID | 요구사항 | 우선순위 | 수용 기준 |
| --- | --- | --- | --- |
| FR-SOL-01 | 싱글 경기를 시작한다 | Must | 서버가 matchId와 7-bag 시드를 발급 |
| FR-SOL-02 | 싱글 결과를 저장한다 | Must | 점수 · 줄 · 레벨 · 놓은 블록 수 저장, 최고 점수 갱신 여부 반환, 같은 경기 두 번 저장 거부 |
| FR-SOL-03 | 싱글 랭킹을 본다 | Must | 최고 점수 TOP 10 + 내 순위 · 점수, 같은 점수는 먼저 달성한 사람이 위 |

### 1.3 vs AI (AI)

| ID | 요구사항 | 우선순위 | 수용 기준 |
| --- | --- | --- | --- |
| FR-AI-01 | AI가 현재 보드에서 다음 수를 고른다 | Must | 보드 · 현재 블록 · 홀드 · 다음 5개 · 받을 방해 줄을 받아 놓을 위치와 입력 순서를 반환 |
| FR-AI-02 | 난이도를 3단계로 나눈다 | Must | EASY · NORMAL · HARD는 탐색 깊이와 입력 재생 속도가 다르고, HARD는 T-스핀을 시도 |
| FR-AI-03 | AI 응답이 늦으면 대체 수를 쓴다 | Must | 150ms 초과 또는 오류 시 FE 규칙 AI로 그 수를 둔다, 게임은 멈추지 않음 |
| FR-AI-04 | vs AI 경기를 시작한다 | Must | 난이도를 받아 matchId · 시드 발급 |
| FR-AI-05 | vs AI 결과를 저장한다 | Must | 내 성적 · AI 성적 · 승패 저장, user\_stats 승패 갱신 |

### 1.4 방 (ROM)

| ID | 요구사항 | 우선순위 | 수용 기준 |
| --- | --- | --- | --- |
| FR-ROM-01 | 방을 만든다 | Must | 6자리 코드(0 · O · 1 · I 제외), 초대 URL, 라운드 수 1 또는 3, 30분 동안 활동 없으면 만료 |
| FR-ROM-02 | 코드나 URL로 방에 들어간다 | Must | 정원 2명, 이미 게임 중이면 거부, 입장하면 다른 사람에게 PLAYER\_JOINED |
| FR-ROM-03 | 방에서 나간다 | Must | 일반 참가자가 나가면 PLAYER\_LEFT, 방장이 나가면 방이 닫히고 ROOM\_CLOSED |
| FR-ROM-04 | 준비 상태를 바꾼다 | Must | 둘 다 준비되면 서버가 경기를 만들고 3초 카운트다운 |

### 1.5 친구 대전 (BAT)

| ID | 요구사항 | 우선순위 | 수용 기준 |
| --- | --- | --- | --- |
| FR-BAT-01 | 같은 시드로 동시에 시작한다 | Must | COUNTDOWN의 startsAt에 두 클라이언트가 시작, 블록 순서가 같음 |
| FR-BAT-02 | 블록 고정을 서버가 검증한다 | Must | lock마다 서버가 보드 · 줄 삭제 · 점수를 재계산, 다르면 INVALID\_LOCK 후 서버 보드로 맞춤 |
| FR-BAT-03 | 상대 보드를 실시간으로 본다 | Must | 상대 lock 후 200ms 안에 BOARD 수신 |
| FR-BAT-04 | 공격과 상쇄 | Must | 아래 1.7 공격 규칙대로 계산, 받을 줄이 있으면 먼저 상쇄, 남은 줄만 ATTACK |
| FR-BAT-05 | 승패를 확정한다 | Must | 먼저 topout한 쪽 패배, GAME\_OVER 방송, MySQL에 matches · match\_players 저장, user\_stats 갱신 |
| FR-BAT-06 | 연결 끊김을 처리한다 | Must | 끊긴 뒤 10초 안에 다시 붙으면 이어서, 못 붙으면 끊긴 쪽 패배(reason DISCONNECT) |
| FR-BAT-07 | 3판 2선승 | Should | 방 생성 시 3을 고르면 먼저 2승한 사람이 최종 승자, 라운드마다 새 시드 |
| FR-BAT-08 | 재대결 | Should | 끝난 뒤 둘 다 수락하면 같은 방에서 새 경기 |

### 1.7 공격 규칙 (FR-BAT-04 기준)

| 동작 | 보내는 줄 |
| --- | --- |
| 1 · 2 · 3 · 4줄 | 0 · 1 · 2 · 4 |
| T-스핀 싱글 · 더블 · 트리플 | 2 · 4 · 6 |
| B2B(테트리스 · T-스핀 줄 삭제가 그 사이 일반 줄 삭제 없이 연속) | +1 |
| 콤보(연속 줄 삭제, 두 번째부터 1) | 콤보 1~2: +1, 3~4: +2, 5~6: +3, 7 이상: +4 |
| 퍼펙트 클리어 | +10 |

상쇄: 보낼 줄 수만큼 내 대기 방해 줄을 먼저 지우고, 남은 만큼만 상대에게 보낸다.

### 1.6 기록 (REC)

| ID | 요구사항 | 우선순위 | 수용 기준 |
| --- | --- | --- | --- |
| FR-REC-01 | 내 최근 경기를 본다 | Must | 모드별 필터, 최신순 페이지(기본 20개) |
| FR-REC-02 | 경기 상세(결과 화면)를 본다 | Must | 참가자별 점수 · 줄 · 공격 보냄/받음 · 최대 콤보 · APM, 승자 표시 |

## 2. 비기능 요구사항

| ID | 요구사항 | 기준 |
| --- | --- | --- |
| NFR-01 | 지연 | 친구 대전 lock → 상대 BOARD 수신 p95 200ms 이하(같은 리전) |
| NFR-02 | 동시 처리 | 동시 100방(200명) 대전에서 서버 CPU 70% 이하 |
| NFR-03 | 공정성 | 클라이언트가 보낸 점수 · 공격량은 믿지 않고 서버 재계산 값만 저장(친구 대전) |
| NFR-04 | 보안 | 게스트 로그인(POST /auth/guest) · AI 상태 확인(GET /ai/v1/health)을 뺀 모든 REST · STOMP 요청은 Access JWT 인증, 토큰 재발급(POST /auth/refresh)은 Refresh 토큰으로 인증, 방에 없는 사람의 구독 · 발행 거부 |
| NFR-05 | 가용성 | AI 서버가 죽어도 vs AI 모드는 FE 규칙 AI로 계속 플레이 가능 |
| NFR-06 | 프레임 | 보드 렌더링 60fps, 입력 지연 1프레임 이내 |
| NFR-07 | 데이터 보존 | 끝난 경기 기록은 1년 보존, 진행 중 상태는 Redis TTL로 자동 정리 |

## 3. 용어

| 용어 | 뜻 |
| --- | --- |
| 7-bag | 7종 블록을 한 묶음으로 섞어 차례로 내는 방식 |
| SRS | 표준 회전 시스템. 벽 차기(킥) 규칙 포함 |
| lock | 블록이 바닥 · 다른 블록에 닿아 고정되는 순간 |
| topout | 새 블록이 나올 자리가 막혀 게임이 끝나는 것 |
| B2B | 테트리스나 T-스핀을 연속으로 해서 받는 보너스 |
| APM | 분당 보낸 공격 줄 수 |
