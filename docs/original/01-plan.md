# 테트리스 대전 게임 — 기획서

Nov 10, 2026 · @ocean

브라우저에서 바로 하는 블록 퍼즐 대전 게임이다. 설치 · 회원가입 없이 닉네임만 넣고 들어와 혼자 점수를 겨루거나, AI와 붙거나, 게임 코드 하나로 친구와 1:1 대전을 한다.

## 1. 배경과 문제

- 기존 웹 블록 퍼즐은 혼자 하는 것이 대부분이고, 친구와 붙으려면 앱 설치 · 계정 생성 · 친구 추가를 거쳐야 한다.
- 점심시간 10분처럼 짧은 틈에 "링크 하나 보내고 바로 한 판"을 하고 싶은 수요가 있다.
- 실력 차이가 큰 친구끼리는 재미가 금방 떨어진다. 혼자 연습할 상대(AI)가 있으면 다시 찾아올 이유가 생긴다.

## 2. 목표

| 구분 | 목표 | 측정 |
| --- | --- | --- |
| 진입 | 첫 접속부터 첫 게임 시작까지 30초 이내 | 게스트 로그인 → 첫 matches 행 생성 시각 차 |
| 대전 | 초대 링크로 들어온 사람의 70% 이상이 실제로 한 판을 끝냄 | 입장 수 대비 FINISHED 경기 수 |
| 재방문 | 첫 게임을 끝낸 사용자 중 7일 안에 다시 와서 게임을 1판 이상 끝낸 비율 25% | 주간 코호트(첫 경기 종료일 기준)의 users.id 중, 첫 경기 다음 날부터 7일 안에 matches 행(FINISHED)이 있는 비율 |
| 공정성 | 같은 시드면 두 사람이 같은 블록 순서를 받음 | 7-bag 시드 공유, 서버 재계산 |

## 3. 대상 사용자

- **직장인 · 학생 친구 무리**: 메신저로 링크를 돌려 짧게 한 판 붙는다.
- **혼자 연습하는 사람**: 랭킹 점수를 올리거나 AI 난이도를 올려 가며 실력을 키운다.

## 4. 게임 모드

### 4.1 싱글 (SOLO)
- 표준 10 × 20 보드, 7-bag 랜덤, 홀드 1칸, 다음 블록 5개 미리 보기.
- 레벨은 지운 줄 10줄마다 1씩 오르고, 낙하 속도가 빨라진다.
- 끝나면 점수를 저장하고 싱글 랭킹(최고 점수 기준 TOP 10 + 내 순위)을 보여 준다.

### 4.2 vs AI (AI)
- 화면을 반으로 나눠 왼쪽은 나, 오른쪽은 AI 보드.
- 난이도 EASY · NORMAL · HARD. 난이도는 AI 서버의 탐색 깊이와 FE의 입력 재생 속도로 조절한다.
- AI 수 계산은 별도 AI 서버가 맡고, 150ms 안에 답이 없으면 FE가 간단한 규칙 기반 수로 대신한다.
- 공격 · 방해 줄 규칙은 친구 대전과 같다. 싱글 · AI 경기는 클라이언트가 판정하고 결과만 서버에 저장한다.

### 4.3 친구 대전 (FRIEND)
- 방장이 방을 만들면 6자리 게임 코드와 초대 URL이 나온다. 정원은 2명.
- 둘 다 "준비"를 누르면 3초 카운트다운 후 같은 시드로 동시에 시작한다.
- 블록을 놓을 때마다 서버에 알리고, 서버가 줄 삭제 · 공격량을 다시 계산해 상대에게 방해 줄을 보낸다.
- 먼저 천장에 닿는 사람이 진다. 연결이 끊기면 10초 기다린 뒤 끊긴 사람의 패배로 처리한다.
- 라운드는 1판으로 진행한다. 3판 2선승은 Should 범위이며, 구현 시 방 생성 시 선택한다.
- 끝난 뒤 "재대결"은 Should 범위로, 시간이 남으면 넣는다.

## 5. 공격 규칙 (요약)

| 동작 | 보내는 줄 |
| --- | --- |
| 1줄 | 0 |
| 2줄 | 1 |
| 3줄 | 2 |
| 4줄(테트리스) | 4 |
| T-스핀 싱글 · 더블 · 트리플 | 2 · 4 · 6 |
| B2B 보너스 | +1 |
| 콤보 | 콤보 수에 따라 0 · 1 · 1 · 2 · 2 · 3 · 3 · 4 … |
| 퍼펙트 클리어 | +10 |

콤보는 줄을 지운 블록 고정이 연속될 때 두 번째부터 1로 센다(첫 줄 삭제는 콤보 0). 줄을 지우지 못한 블록이 한 번 고정되면 콤보는 0으로 초기화된다.

받을 방해 줄이 쌓여 있을 때 내가 줄을 지우면 먼저 상쇄한다. 방해 줄의 구멍 위치는 서버가 정한다.

## 5-1. 점수 규칙 (싱글 · 랭킹 공통)

| 동작 | 점수 |
| --- | --- |
| 1 · 2 · 3 · 4줄 | 100 · 300 · 500 · 800 × 현재 레벨 |
| T-스핀 싱글 · 더블 · 트리플 | 800 · 1200 · 1600 × 현재 레벨 |
| B2B | 위 점수 × 1.5 |
| 콤보 | 50 × 콤보 수 × 현재 레벨 |
| 소프트 드롭 · 하드 드롭 | 칸당 1 · 2 |

싱글 · vs AI는 클라이언트가 판정하므로 결과 저장 때 서버가 그럴듯함을 검사한다. 시드와 놓은 블록 수 · 지운 줄 수 · 플레이 시간으로 점수 상한을 계산해 넘으면 저장은 하되 랭킹에서 뺀다(조작 의심 표시). 랭킹은 Redis Sorted Set이지만 원본은 MySQL user_stats.solo_best_score이며, Redis가 비면 MySQL에서 다시 채운다.

## 6. 범위

| 우선순위 | 기능 |
| --- | --- |
| Must | 게스트 로그인, 싱글 플레이 · 점수 저장 · 랭킹, vs AI 3단계, 친구 대전 방 생성 · 입장 · 준비 · 대전 · 결과, 최근 경기 기록 |
| Should | 재대결, 3판 2선승, 카카오 로그인으로 게스트 계정 이어 받기 |
| Won't (이번 범위 밖) | 공개 매칭(랜덤 상대), 3인 이상 대전, 관전, 채팅, 모바일 앱, 결제 |

## 7. 기술 구성

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| FE | React 19 + TypeScript + Canvas | 60fps 보드 렌더링, 게임 루프는 FE가 소유 |
| BE | Spring Boot 3 (Java 21), STOMP over WebSocket | 방 · 대전 중계, 서버 재계산 |
| AI | Python FastAPI | 수 탐색(빔 서치 + 휴리스틱 평가) |
| 저장 | MySQL 8(회원 · 끝난 경기), Redis 7(방 · 진행 중 상태 · 랭킹 · 토큰) | 진행 중 상태는 휘발성, 기록만 영속 |
| 배포 | Docker Compose, Nginx(WebSocket 프록시), 단일 EC2 | 4주 프로젝트 규모 |

## 10. 위험과 대응

| 위험 | 대응 |
