# 테트리스 대전 게임 — 요구사항 명세서

개정 2판 · 2026-11-12 · 작성 오션(팀장)

기획서의 Must·Should 범위를 기능 요구사항(FR), 게임 규칙(GR), 업무 규칙(BR), 비기능 요구사항(NFR)으로 나눈다. 게임 규칙과 업무 규칙의 값은 이 문서가 원본이며, 다른 문서는 번호로 가리킨다. FR 번호는 API 명세서의 "요구사항" 칸과 맞춘다.

## 1. 기능 요구사항

### 1.1 회원·싱글·vs AI

| ID | 요구사항 | 우선순위 | 수용 기준 |
| --- | --- | --- | --- |
| FR-USR-01 | 게스트 로그인과 토큰 수명 관리 | Must | 닉네임은 한글·영문·숫자 2~10자. 서버가 그 닉네임에서 아직 안 쓰인 4자리 태그(0000~9999)를 무작위로 붙인다. 같은 닉네임으로 다시 로그인하면 새 게스트 계정이 생긴다(게스트는 비밀번호가 없어 기존 계정을 찾지 않는다). Access 토큰(1시간)은 응답 본문, Refresh 토큰(7일)은 HttpOnly 쿠키로 준다. Refresh 쿠키로 Access 토큰을 재발급하면서 Refresh 토큰을 회전하고, 만료·폐기·이미 쓴 Refresh는 거부한다. 로그아웃하면 Redis의 Refresh를 지우고 쿠키를 비운다 |
| FR-USR-02 | 카카오 계정 연결과 카카오 로그인으로 이어 받기 | Should | 연결 뒤에도 같은 userId·전적 유지, user_type은 MEMBER가 된다. 이미 다른 계정에 연결된 카카오 계정은 거부한다. 다른 기기에서 연결된 카카오 계정으로 로그인하면 그 계정을 이어 받고, 연결되지 않은 카카오 계정이면 새 계정을 만들지 않고 거부한다 |
| FR-USR-03 | 내 정보와 전적 요약 | Must | 닉네임#태그, 계정 종류, 싱글 판 수·최고 점수, vs AI 승패, 친구 대전 승패 |
| FR-SOL-01 | 싱글 경기 시작과 결과 저장 | Must | 시작하면 서버가 matchId와 7-bag 시드를 발급하고 matches 행을 PLAYING으로 만든다. 끝나면 점수·줄·레벨·놓은 블록 수·최대 콤보·플레이 시간을 저장하고, BR-07 상한 검사를 통과해야 최고 점수·랭킹에 반영한다. 최고 점수 갱신 여부와 랭킹 반영 여부를 돌려준다. 같은 경기를 두 번 저장하면 거부한다 |
| FR-SOL-02 | 싱글 랭킹 | Must | 최고 점수 TOP N(기본 10, 최대 50) + 내 순위·점수. 동점은 그 점수를 먼저 달성한 사람이 위(BR-08) |
| FR-AI-01 | AI 서버의 다음 수 계산과 난이도 | Must | 보드(22행)·현재 블록·홀드·홀드 가능 여부·다음 5개·받을 방해 줄 수를 받아 홀드 사용 여부·회전·열·입력 순서를 반환한다. 탐색 깊이: VERY_EASY 1수·홀드 없음·60% 확률로 평가 상위 6개 중 하나, EASY 1수 + 30% 확률로 두 번째 수, NORMAL 1수, HARD 2수(다음 블록까지), IMPOSSIBLE 2수 + T-스핀 자리 탐색. FE 입력 재생 간격: EASY·NORMAL 300ms, HARD 150ms, IMPOSSIBLE 60ms. 블록당 최소 시간(생성→고정): VERY_EASY 2.5초, EASY 2초, NORMAL 1.5초, HARD 1초, IMPOSSIBLE 제한 없음 (T-35 개정) |
| FR-AI-02 | AI 응답 지연·실패 때 대체 수 | Must | FE가 요청을 보낸 시각부터 응답을 받은 시각까지 150ms를 넘기거나, 네트워크 오류·4xx·5xx가 나면 그 수만 FE 규칙 AI(GR-09)로 둔다. 게임은 멈추지 않고, 늦게 온 응답은 버린다 |
| FR-AI-03 | vs AI 경기 시작과 결과 저장 | Must | 난이도를 받아 matchId·시드를 발급하고 matches 행을 PLAYING으로 만든다. AI 보드도 같은 시드를 쓴다. 끝나면 승패, 내 성적, AI 성적(점수·줄·레벨·블록 수·공격 보냄/받음·최대 콤보)을 저장하고 BR-09로 승패를 갱신한다. 내 성적은 BR-07 상한 검사를 거친다 |

### 1.2 방·친구 대전·기록

| ID | 요구사항 | 우선순위 | 수용 기준 |
| --- | --- | --- | --- |
| FR-ROM-01 | 방 생성 | Must | 6자리 코드(대문자·숫자, 0·O·1·I 제외, 활성 방끼리 중복 없음)와 초대 URL을 만든다. 라운드 수는 1(Must) 또는 3(Should, FR-BAT-03). 30분 동안 활동이 없으면 만료(BR-01). 이미 다른 활성 방에 있는 사용자는 만들 수 없다 |
| FR-ROM-02 | 방 조회·입장·퇴장 | Must | 입장 전 조회로 방 상태·참가자·라운드 수를 본다. 정원 2명, WAITING이 아닌 방과 다른 활성 방에 있는 사용자는 입장 거부. 입장하면 상대에게 PLAYER_JOINED. 일반 참가자가 나가면 PLAYER_LEFT, 방장이 나가면 방이 닫히고 ROOM_CLOSED. 경기 중에 나가면 나간 쪽 패배(BR-04) |
| FR-ROM-03 | 준비와 카운트다운 | Must | 준비·취소를 바꿀 수 있다. 두 사람이 모두 준비되면 서버가 matches 행을 만들고 COUNTDOWN을 보낸다. startsAt은 서버가 COUNTDOWN을 보낸 시각 + 3,000ms다 |
| FR-BAT-01 | 같은 시드로 시작, 서버 검증, 상대 보드·공격 전달 | Must | 두 클라이언트가 COUNTDOWN의 startsAt에 같은 블록 순서로 시작한다. lock마다 서버가 BR-05로 검증·재계산하고, 맞지 않으면 그 플레이어에게 INVALID_LOCK과 서버 보드를 보낸다. 처리 뒤 두 사람에게 BOARD를 보내고(지연 기준 NFR-01), GR-08로 상쇄한 뒤 남은 공격은 ATTACK으로 보낸다 |
| FR-BAT-02 | 승패 확정과 연결 끊김 | Must | BR-04로 판정해 GAME_OVER를 보내고 matches·match_players를 저장, BR-09로 전적 갱신. 연결이 끊기면 BR-06대로 10초 재접속을 기다리고, 다시 붙으면 RESYNC로 이어서 한다 |
| FR-BAT-03 | 3판 2선승과 재대결 | Should | 방 생성 때 3을 고르면 BR-03대로 먼저 2승한 사람이 시리즈 승자다. 라운드마다 새 시드, 라운드 사이 5초 카운트다운. 시리즈가 끝난 뒤 두 사람이 모두 재대결을 수락하면 같은 방에서 새 시리즈(series_no + 1)를 시작하고, 한 사람이라도 거절하거나 나가면 재대결은 없다 |
| FR-REC-01 | 최근 경기 목록과 경기 상세 | Must | 목록: 내가 참가한 FINISHED·ABORTED 경기, 모드별 필터, started_at 내림차순, 기본 20개·최대 50개 페이지. 상세: 참가자만 볼 수 있고 참가자별 점수·줄·레벨·블록 수·공격 보냄/받음·최대 콤보·APM, 승자와 종료 사유를 보여 준다 |

## 2. 게임 규칙 (GR)

세 모드 모두 같은 규칙을 쓴다. FE 엔진과 친구 대전 서버 재계산이 이 규칙으로 같은 결과를 내야 한다.

### 2.1 보드·조작·고정

| ID | 규칙 | 내용 |
| --- | --- | --- |
| GR-01 | 보드와 블록 | 보드는 가로 10열 × 세로 22행이고 위 2행은 화면에 보이지 않는다(보이는 영역 10 × 20). 블록은 I·O·T·S·Z·J·L 7종이다. 7-bag: 7종을 한 묶음으로 섞어 차례로 내고, 묶음이 끝나면 다시 섞는다. 섞기는 시드를 넣은 같은 난수 생성기(mulberry32)를 써서 FE·BE·AI가 같은 순서를 만든다 |
| GR-02 | 조작 | 키보드만 지원한다. ←/→ 이동, ↑ 시계 방향 회전, Z 반시계 방향 회전, ↓ 소프트 드롭, Space 하드 드롭, C 홀드, Esc 일시정지(싱글만). 좌우 이동 자동 반복은 처음 167ms 뒤 33ms 간격 |
| GR-03 | 낙하와 레벨 | 레벨은 1부터 시작해 지운 줄 10줄마다 1씩 오른다. 한 칸 낙하 간격(ms): 1레벨 1000, 2레벨 793, 3레벨 618, 4레벨 473, 5레벨 355, 6레벨 262, 7레벨 190, 8레벨 135, 9레벨 94, 10레벨 64, 11레벨 43, 12레벨 28, 13레벨 18, 14레벨 11, 15레벨 이상 7. 소프트 드롭은 50ms마다 한 칸 |
| GR-04 | 생성·회전·고정·홀드·topout | 새 블록은 숨김 2행 중앙(3~6열)에 나온다. 회전은 SRS 벽 차기를 적용한다. 바닥이나 다른 블록에 닿으면 500ms 뒤 고정되며, 그 사이 이동·회전에 성공하면 다시 500ms를 센다(블록당 최대 15번). 하드 드롭은 즉시 고정. 홀드는 블록 하나가 고정될 때까지 1번만 쓸 수 있다. 새 블록이 나올 자리가 막히면 topout으로 게임이 끝난다. 다음 블록은 5개 미리 보여 준다 |

### 2.2 판정·점수·공격

| ID | 규칙 | 내용 |
| --- | --- | --- |
| GR-05 | T-스핀 | T 블록이 고정될 때 마지막 성공 동작이 회전이고, T 중심 기준 대각선 네 칸 중 3칸 이상이 막혀 있으면(벽·바닥 포함) T-스핀이다. 미니 T-스핀은 구분하지 않는다 |
| GR-06 | 콤보와 B2B | 콤보: 줄을 지운 고정이 연속되면 두 번째부터 1, 2, 3…으로 센다(첫 줄 삭제는 콤보 0). 줄을 못 지운 고정이 한 번 나오면 콤보는 끊긴다. B2B: 테트리스(4줄)나 줄을 지운 T-스핀을 "어려운 삭제"라 하고, 직전 줄 삭제도 어려운 삭제였으면 B2B다. 일반 1~3줄 삭제가 끼면 B2B가 끊긴다. 줄을 못 지운 고정은 B2B를 끊지 않는다. 점수 배율과 공격 보너스 모두 이 조건을 쓴다 |
| GR-07 | 점수 | 레벨은 줄을 지우기 직전 레벨을 쓴다. ① 기본: 1·2·3·4줄 100·300·500·800, T-스핀 0·1·2·3줄 400·800·1200·1600, 여기에 레벨을 곱한다. ② B2B면 ①에 1.5를 곱한다. ③ 콤보 점수 50 × 콤보 × 레벨을 더한다. ④ 드롭 점수(소프트 칸당 1, 하드 칸당 2)를 더한다. 소수점은 한 고정의 계산이 끝난 뒤 버린다. 퍼펙트 클리어는 점수를 더하지 않는다. 예: 3레벨에서 B2B 테트리스에 콤보 2면 800 × 3 × 1.5 + 50 × 2 × 3 = 3,900 |
| GR-08 | 공격·상쇄·방해 줄 | 보내는 줄: 1·2·3·4줄 0·1·2·4, T-스핀 1·2·3줄 2·4·6, B2B +1, 콤보 1~2 +1·3~4 +2·5~6 +3·7 이상 +4, 퍼펙트 클리어(삭제 뒤 보드가 빔) +10. 보낼 줄 수만큼 내 대기 방해 줄을 먼저 지우고 남은 줄만 상대 대기열에 넣는다. 한 번 받은 공격(한 묶음)은 모든 줄의 구멍이 같은 열이고, 묶음마다 구멍 열을 무작위로 정한다(친구 대전은 서버, vs AI는 FE). 대기열의 방해 줄은 그 플레이어가 줄을 못 지운 블록을 고정하는 순간 전부 아래에서 올라온다. 예: 대기 3줄인 상태에서 콤보 없이 B2B 테트리스(4 + 1 = 5줄)를 하면 3줄을 상쇄하고 2줄을 보낸다 |
| GR-09 | FE 규칙 AI | 놓을 수 있는 모든 회전·열에 대해 하드 드롭한 결과를 평가해 점수가 가장 높은 수를 둔다. 평가 = −0.51 × 열 높이 합 + 0.76 × 지운 줄 수 − 0.36 × 구멍 수 − 0.18 × 울퉁불퉁함(이웃 열 높이 차 합). 실수: EASY는 30% 확률, NORMAL은 10% 확률로 두 번째로 좋은 수를 둔다. HARD·IMPOSSIBLE은 실수 없음. 입력 재생 간격은 FR-AI-01과 같다 |

## 3. 업무 규칙 (BR)

### 3.1 방·경기·시리즈·승패

| ID | 규칙 | 내용 |
| --- | --- | --- |
| BR-01 | 방 상태와 만료 | game_rooms.status는 생성 때 WAITING, 카운트다운 시작 때 PLAYING, 시리즈 승자 확정 때 FINISHED, 닫힐 때 CLOSED다. 허용 전이: WAITING→PLAYING, PLAYING→FINISHED, FINISHED→PLAYING(재대결), FINISHED→CLOSED, WAITING→CLOSED, PLAYING→CLOSED. 닫히는 경우: 방장이 나감, 모든 참가자가 나감, 30분 동안 활동 없음(Redis 방 키 만료). 활동은 입장·퇴장·준비·lock·재대결 수락이다. 만료나 복구 불가가 확인되면 status를 CLOSED, closed_at을 확인 시각으로 바꾸고, 진행 중 경기가 있으면 ABORTED로 닫는다 |
| BR-02 | 경기 행의 수명 | 싱글·AI는 경기 시작 API 때, 친구 대전은 COUNTDOWN 때 matches 행을 PLAYING으로 만든다. 끝나면 FINISHED(결과 확정) 또는 ABORTED(무효)로 바꾼다. 결과가 저장되지 않은 싱글·AI 경기는 시작 2시간 뒤 ABORTED로 닫는다 |
| BR-03 | 시리즈와 라운드 | 한 방에서 시리즈 번호(series_no)는 1부터 시작해 재대결마다 1 늘어난다. 라운드 수가 1이면 한 판, 3이면 먼저 2승한 쪽이 시리즈 승자다. 라운드마다 새 시드를 쓰고, 라운드 사이에 5초 카운트다운 뒤 다음 라운드를 시작한다. 무승부·ABORTED 라운드는 승수에 넣지 않고 같은 라운드 번호를 다시 한다(시도 번호 attempt_no + 1). 시리즈 도중 한쪽이 나가면 남은 쪽이 시리즈 승자다 |
| BR-04 | 승패 판정 | 먼저 topout한 쪽이 진다(reason TOP_OUT). 서버가 첫 topout을 받은 뒤 100ms 안에 상대 topout도 오면 그 라운드는 무승부(reason DRAW, 승자 없음)다. 경기 중 방을 나가면 나간 쪽 패배(reason LEFT), 재접속 유예가 지나면 끊긴 쪽 패배(reason DISCONNECT) |

### 3.2 대전 검증·연결 끊김

| ID | 규칙 | 내용 |
| --- | --- | --- |
| BR-05 | 친구 대전 서버 검증 | 클라이언트는 lock마다 seq·블록·회전·위치·홀드 사용 여부·마지막 동작·자기가 계산한 지운 줄 수를 보낸다. 서버는 ① seq가 직전 + 1인지(같으면 무시, 건너뛰면 INVALID_LOCK) ② 블록이 시드 순서·홀드 상태로 나올 수 있는 블록인지 ③ 그 위치가 서버 보드에서 겹치지 않고 바로 아래가 막혀 있는지 검사하고, GR-05~GR-08로 줄 삭제·점수·공격을 다시 계산한다. 하나라도 어긋나거나 지운 줄 수가 다르면 INVALID_LOCK을 보내고 서버 보드를 원본으로 한다. 클라이언트가 보낸 점수·공격량은 쓰지 않는다. 시작 위치에서 그 자리까지 실제로 갈 수 있었는지(경로)는 검사하지 않는다 |
| BR-06 | 연결 끊김과 재접속 | 경기 중 WebSocket이 끊기면 상대에게 PLAYER_LEFT(reason DISCONNECTED)를 보내고 10초 동안 기다린다. 그동안 상대 경기는 계속되고 끊긴 쪽 보드는 멈춘다(방해 줄은 대기열에 쌓인다). 10초 안에 같은 사용자가 다시 연결하면 패배 타이머를 취소하고 RESYNC(자기 보드·seq·홀드·대기 방해 줄·상대 보드)를 보낸 뒤 이어서 한다. 10초가 지나면 끊긴 쪽 패배(BR-04)로 확정한다. 두 사람이 모두 끊겨 10초가 지나면 경기는 ABORTED다 |

### 3.3 점수 검사·랭킹·전적·보존

| ID | 규칙 | 내용 |
| --- | --- | --- |
| BR-07 | 싱글·AI 점수 상한 검사 | 결과 저장 때 서버가 제출값을 검사한다. ① 레벨 = 1 + (지운 줄 ÷ 10의 몫) ② 지운 줄 ≤ ((놓은 블록 × 4 + 받은 공격 줄 × 9) ÷ 10의 몫), 싱글은 받은 공격 줄이 0 ③ 놓은 블록 ≤ 플레이 시간(ms) ÷ 100 ④ 점수 ≤ 레벨 × (지운 줄 × (1,200 + 50 × 최대 콤보) + 놓은 블록 × 400) + 40 × 놓은 블록. 상한은 일부러 넉넉하게 잡아 정상 기록이 걸리지 않게 한다. 하나라도 어기면 결과는 저장하되 ranked = false로 표시하고 최고 점수·랭킹에는 반영하지 않는다 |
| BR-08 | 랭킹 | 랭킹 원본은 MySQL user_stats의 solo_best_score와 solo_best_achieved_at이다. Redis Sorted Set은 조회 캐시이며 점수 = solo_best_score × 10,000,000 + (9,999,999 − 달성 순번)으로 넣어 동점이면 먼저 달성한 사람이 위에 오게 한다. 달성 순번은 Redis 카운터로 발급한다. Redis가 비어 있으면 MySQL에서 solo_best_achieved_at 오름차순으로 순번을 다시 매겨 채운다. ranked = false 결과와 싱글 기록이 없는 사용자는 랭킹에 없다 |
| BR-09 | 전적 갱신 | 경기가 FINISHED로 확정될 때 user_stats를 한 트랜잭션으로 갱신한다. 싱글: solo_games + 1, ranked이고 최고 점수를 넘으면 solo_best_score·solo_best_achieved_at 갱신. AI: 승이면 ai_wins, 패면 ai_losses + 1. 친구 대전: 라운드마다 승자 friend_wins, 패자 friend_losses + 1. ABORTED 경기와 result가 NONE인 참가자(무승부 포함)는 갱신하지 않는다. GUEST도 같은 기준이다 |
| BR-10 | 기록 보존 | 끝난 경기(matches·match_players)와 닫힌 방(game_rooms)은 1년 보존한다. 매일 04:00(KST)에 ended_at·closed_at이 1년 지난 행을 지운다. 진행 중 상태는 Redis TTL로 정리한다(ERD 명세서 6장) |
