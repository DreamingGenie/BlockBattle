# T-17 동시 100방 부하 시험 결과 (로컬 근사 측정)

> **이 결과는 로컬 PC의 Docker에서 잰 근사값이다.** 백엔드 컨테이너를 CPU 2개·메모리 4GB로 제한했고,
> k6·MySQL·Redis가 같은 호스트에서 돌았다(네트워크 지연은 실제보다 작고, 호스트 CPU 경합은 크다).
> CPU는 node exporter가 아니라 docker stats로 쟀다. **같은 리전 2 vCPU·4GB 서버에서의 공식 합격 판정(REQ-016·REQ-017·REQ-022)을 대신하지 않는다.**

- 실행: 방 100개(가상 사용자 200명), 30초 동안 늘린 뒤 90초 유지. 지표는 유지 구간만 기록
- k6 종료 코드: 99 (0 = thresholds 모두 통과)

## 부하 프로필 재현 정도 (REQ-017)

- lock 전송: 14205회 → 플레이어당 초당 0.79회 (목표 2회). 직전 BOARD를 못 받아 건너뛴 틱 26회
- 부하 발생기 k6 컨테이너 CPU 평균: 1800%(1코어 = 100%) — 같은 호스트(22코어)에서 서버와 CPU를 나눠 쓴다
- 지연 분해(같은 호스트 시계, BOARD 봉투 sentAt 기준): lock → 서버 발송 p95 101.0ms, 서버 발송 → 봇 수신 p95 997.0ms
- topout(재대결로 이어 감): 88회 — 재대결 카운트다운 3초 동안은 lock이 멈춘다
- ATTACK 989회·3226줄 → 방당 10초에 3.6줄
- 10초 구간 중 양방향 모두 2줄 이상 ATTACK이 있었던 비율: 159/900 = 18%
