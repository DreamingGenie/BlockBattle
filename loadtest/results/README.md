## 부하 프로필을 다 재현하지 못한 부분 (REQ-017)

- lock 빈도는 플레이어당 초당 **1.80회**로 목표 2회의 90%다. 봇이 topout하면(10분에 1,319회) 재대결 카운트다운 3초 동안 lock이 멈추기 때문이다.
- '10초마다 2줄 이상 공격이 오가도록'은 10초 구간 중 양방향 모두 2줄 이상 ATTACK이 있었던 비율이 **42%**다. 방당 10초에 7.5줄이 오가지만, 받은 방해 줄 때문에 봇의 우물 전략이 자주 깨진다.
- 따라서 이 측정은 목표 프로필보다 lock 부하가 약 10% 낮은 상태에서 쟀다. CPU 52%와 p95 18ms에는 여유가 있지만, 공식 측정 전에 봇 전략을 더 다듬어 프로필을 맞추는 것이 좋다.

## 측정 방식 차이

- CPU: node exporter 대신 docker stats(5초 간격). 2 vCPU 기준 = docker CPU% ÷ 2
- 지연: 한 k6 VU가 한 방의 두 연결을 모두 열어 lock 전송 시각과 상대 연결의 BOARD 수신 시각을 같은 시계로 잰다. 진단용으로 BOARD 봉투의 sentAt(서버 시각, 같은 호스트 시계)으로 구간을 나눴다.
- 네트워크: 같은 호스트의 Docker 네트워크라 실제 리전 내 지연보다 작다.
